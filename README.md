# Wayfare

An Android trip planner. Save places, arrange them into days, and take the lot
with you — it keeps working when the signal doesn't.

It began as an app for one family's week in Scotland, and everything specific
to that trip has since been taken out. What is left works anywhere: you tell it
where you're going and who's coming, and the rest follows from that.

The app has three tabs:

- **Trip** — the plan before you go and today's stops while you're there. Days
  hold saved places with times; the next stop is flagged, with walking times
  between stops and the forecast at the top. Kids' activities, the budget and
  the notes and packing checklist are reached from here.
- **Find** — what's on near you, over the dates you choose: events, cinema,
  theatre, children's sessions, places nearby, a weekly check before the
  weekend, and whole days out with the stops in order. There is also an "Ask
  somewhere else" route: copy a ready-made question into any assistant and
  paste the answer back.
- **Saved** — everything you've saved, grouped by area, filtered by All / To do /
  Eat / On, with search once you have a few.

A Kids / Adults switch in the top bar changes what is suggested and how searches
are worded.

## What needs signal, and what doesn't

Your places, the plan, notes, the budget and the packing list are stored on the
device and work with no connection at all. Forecasts are cached, so the last one
fetched stays readable offline.

Searching, exploring, and refreshing the weather need a connection. So do map
tiles the first time you look at them — **Settings → Offline maps** downloads the
area around your saved places so maps still draw where there's no signal. The app
shows a banner when it's offline rather than letting each feature fail in its own
words.

Nothing is stored anywhere but the phone, so **Settings → Backup** exports a file
worth keeping; the app tells you how long it's been.

## Getting the APK

Every push to this repo builds a debug APK automatically via GitHub Actions. The
same committed debug keystore signs each debug build, so a newer APK can be
installed over the previous one without uninstalling it or losing local trip
data. The Android `versionCode` is generated from the GitHub run number.

1. Go to the repo's **Actions** tab → **Build Android APK** → latest run.
2. Download the `wayfare-debug-apk` artifact (a zip containing `app-debug.apk`).
3. Copy the APK to your Android phone and open it to install (you'll need to allow "install from unknown sources" for the app you use to open it, since it isn't from the Play Store).

For a signed release, run **Release Android APK** manually. It requires these
GitHub Actions secrets: `ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and
`ANDROID_KEY_PASSWORD`. The release keystore is reconstructed only during the
build and is never committed.

**Back up your trips before switching to a release build.** Debug and release
builds share the app ID but are signed with different keys, so Android will not
install one over the other: you have to uninstall first, and uninstalling
deletes everything the app has saved. Use Settings → Export backup, install the
release build, then import the backup.

**Builds can't be rolled back in place.** `versionCode` now rises with every CI
run and Android refuses to install a lower one over a higher one. Going back to
an older APK - including any from before versioning was added, which were all
version 1, or a local build - means uninstalling first, with the same data loss.

**Keep the release keystore safe.** Without it the app can never be updated
again. Enable Play App Signing and keep a copy somewhere other than GitHub.

## Project structure

- `www/` — the app itself (plain HTML/CSS/JS, no build step; Leaflet is vendored, everything else is fetched at runtime)
- `www/js/data.js` — all trip content (itinerary, places, budget, tips, packing list) — edit this file to change the plan
- `android/` — native Android project generated by [Capacitor](https://capacitorjs.com/), which wraps `www/` in a WebView
- `.github/workflows/build-apk.yml` — CI that builds the update-safe debug APK on every push
- `.github/workflows/release-apk.yml` — manual signed release APK/AAB workflow

## Building locally

Requires Node.js and Android SDK / Android Studio.

```bash
npm install
npx cap sync android
cd android
./gradlew assembleDebug
# APK at android/app/build/outputs/apk/debug/app-debug.apk

# Optional: local release build, unsigned unless release signing variables are set
./gradlew assembleRelease
```

To edit the trip content, change `www/js/data.js` and re-run `npx cap sync android` before rebuilding.
